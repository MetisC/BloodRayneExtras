# BloodRayne: Terminal Cut — Extras mod

A standalone `dinput8.dll` proxy for **BloodRayne: Terminal Cut** (GOG) that
adds a persistent **"All powers and combos"** option, two custom challenge
arenas and a model-swap system — no files inside the game's PODs are ever
modified.

## Challenge arenas

Four extra rows appear in **New Game** before *Training*:

- **Challenge Combat: Normal / Hard / Extreme** — soldier waves in a
  boiler-room arena (8/10/10 waves; elites on Hard and Extreme). A shared
  best-time record is kept in `br1mod.ini` (`[Challenge] BestTime`) and
  shown in the menu labels.
- **Boss Battle** — officers + sub-officers plus a boss (NAZI_BARROCK,
  1200 HP) over 6 waves. Separate record: `[Challenge] BestBoss`.

Native HUD feedback during fights: `OLEADA n/N` per wave and
`COMPLETADO! m:ss` on completion via the game's own message renderer
(`0x4715c0`).

The arenas are loose files (`world/challenge.*`, `world/bossbattle.*`)
generated by `MODDING/tools/gen_survival.py` / `gen_boss.py` — delete them
and the menu rows disappear with the missions.

## Appearance swap

`[Appearance]` ini section rewrites the mission's `modelName` fields at
launch time (file-level, before the engine loads it):

- `Soldier=` / `Elite=` — any model sharing the soldier skeleton:
  `SOLDIER`, `SS_SOLDIER`, `SS_OFFICER`, `GGG_OFFICER`, `GGG_ELITE`,
  `GGG_HAZMAT`, `GGG_JETPACK`, `STALKER`, `ARGSLAVE`, `ARGSLAVESHIRT`,
  `NAZI_BARROCK` (all `.DFM`).
- `Boss=` — either a **hero name** or a model file:
  - `Mynce`, `Butcheress`, `Rayne`, `RayneLA` — rewrites Boss1 as a
    `CMainCharacter` with the matching `heroType` (2/3/1/4): the real
    dhampir model (`MENTOR.SKL`, `butcheress.skl`, `Rayne.skl`), boss AI
    and full move set, mirroring the native `MentorBoss0` block.
  - `*.DFM` — plain `modelName` swap: CSoldier models keep the soldier
    block; NPC models (`BUTCHERESS`, `KRISTINE`, `KAZI`, `GMONEY`, `HICKS`,
    `OLDMAN`, `BATMITE`, `RAYNE`, `VAMPETTE`, `VAMP`) automatically turn
    Boss1 into a `CNPC` actor (restored to `CSoldier` when removed).

Leave the keys unset/commented for stock models.

> Mynce appears twice in the campaign: the maroon mentor outfit (Act 1
> intro, `LA_*`) and the G.G.G. officer look (Act 3, `DE_C3DOME`). Both
> use `heroType=2` / `MENTOR.SKL` — the nazi outfit is applied by the
> mission's own scripting (attachments/texture override), so the arena
> boss spawns with the base mentor skin.
> The Countess (Bathory) has no dedicated model in the shipped assets.

## Testing

`MODDING/tools/test_boss_run.ps1` — fully autonomous end-to-end run:
launches the game, walks the title screen via posted window messages,
injects the menu action through process memory and watches
`br1mod_trace.log` for wave progress. `Autokill=1` in `[Challenge]` makes
the player invincible and auto-clears waves for unattended verification
(testing only — do not ship enabled).

## Features

- New cycler row at the top of **New Game**: *All powers and combos: Yes/No*
  (before *Training*), localized for all six official languages
  (EN/ES/FR/IT/RU/JA) and persisted in `br1mod.ini` (`[Powers] all`).
- When **Yes**, the mod replicates the classic "everything unlocked" script
  mod at runtime, in memory only:
  - `setSlowMoAvailability(true)` + `setZoomAvailability(true)` injected at
    level start,
  - `setComboLevel(5,5)` — every restrictive `setComboLevel(a,b)` is
    repointed to the max,
  - `flagOn(powerMovesAreAvailable)` injected — unlocks the power-move
    table the engine gates via `0x499A06`,
  - `flagOn(disableHarpoon[Jump])` rewritten to `flagOff(...)` — harpoon
    and harpoon jump always available.
- When **No**, level scripts run 100% stock.
- Works from the Training level through every act (LA/AR/DE), because the
  recipe is applied to the first command fetch of each level script's real
  execution pass — the same place the old `WORLD.POD` mod put its setup.

## How it works

`rayne1.exe` imports `DirectInput8Create` from `dinput8.dll`, so the proxy
shadows the system DLL in the game folder. Forwarding resolves the export
RVA from a pristine on-disk image (another component hooks the in-memory
export, which would loop back into us otherwise).

Three inline patches (`push addr; ret`, byte-verified against the exe):

- `0x4C89AE` — inside the New Game menu builder, appends our row before
  Training. Action code `0x150` toggles the ini value and reuses the native
  menu-rebuild path (`0x4CE0C6`).
- `0x4CCD46` — action dispatch load; intercepts `0x150`.
- `0x510EC2` — script-command fetch inside the level-script executor
  (`0x510E40`). In real-execution mode (`[0x1E4B570] == 0`), slot 0 is
  replayed (return lands past `inc eax`) so the four setup commands run
  before the level's first real command; restrictive commands are
  repointed to unlocked equivalents kept in our own buffers.

All addresses are resolved against `GetModuleHandle(NULL)` at runtime —
`rayne1.exe` is ASLR-relocated.

## Build

x86 Native Tools prompt:

```
build.bat
```

Produces `dinput8.dll`. Deploy next to `rayne1.exe` with `br1mod.ini`.

## Install / uninstall

- Install: copy `dinput8.dll` + `br1mod.ini` next to `rayne1.exe`.
- Uninstall: delete those two files. Saves, PODs and `PCPOD.INI` are never
  touched.
